## 一、现状差距

设计稿是 19 种情绪、9 条课程场景接入规则、一套明确的动效参数；代码里只有 5 个状态，而且**没有任何一条赋值路径**。

| 项 | 设计稿 | 当前代码 | 差距 |
|---|---|---|---|
| 情绪数量 | 19 | `BotMood { Idle, Focus, Soon, Done, Alert }` 5 个 | 缺 14 种 |
| 驱动源 | 课程状态机 + 调度器插播 | `WidgetWindow.xaml` 写死 `Mood="Idle"`，全仓 grep 无其它赋值 | 表情永远待机 |
| 坐标系 | `viewBox 0 0 120 120`，眼 `cx 44.5/75.5, cy 60, rx 7.4, ry 13` | `Grid 64×64`，眼 `6.8×11.2` | 形变数值（`translate(-3.5px)`、`scaleY(.08)`）按 120 写，套到 64 会差近一倍 |
| 壳体 | 横向鹅卵石 `rect 92×48 rx24` + 底部投影 + 顶部高光 | 近正圆 `54×50` 椭圆 | 形象不同 |
| 眼形层 | 椭圆 / 上弧 / 深弧 / 圆 / X / 感叹号 / 心形 七种 | 只有椭圆 + 上弧 | 缺五种 |
| 动效 | 切换 260–420ms 弹簧、光色 180ms、blink 4–6s、wander 25–40s | blink 3.2–7.4s、glance 9–18s、形变 160ms `CubicEase` | 参数全部不符 |
| 瞬态回退 | blink/wander/laugh/surprise 播完必回退 | 无瞬态概念，回退靠动画链手写 | 无统一播放器 |
| 无障碍 | `prefers-reduced-motion` 关瞬态 | 无 | 缺 |

这解释了为什么悬浮窗里的团子「一直一个样」：不是动效不够，是根本没人给它状态。

## 二、范围

### 2.1 做

1. **19 种情绪的形状预设**：全部实现（成本在数据表，不在分支代码），但只有设计稿第 03 节的 9 个场景接入驱动。
2. **纯状态机**：`课程/交互信号 → 稳态表情`，放 Domain 层，可脱离 WPF 单测。
3. **瞬态播放器**：blink / wander / wink / laugh / surprise，同一时刻只播一个、可被打断、播完回到「当时重新解析出来的稳态」。
4. **BotView 重构**：120 坐标系重排、七种眼形、弹簧曲线、光色过渡、reduced-motion。

- 小尺寸（< 32px）眼距放大规则：悬浮窗按 44×44 显示，不触发；将来主窗口若也用团子再补。

## 三、关键设计决策

**1. 枚举与预设表放 `FuShi.Domain`，不放 App。**
测试项目 `FuShi.Tests` 是 `net8.0`，只引用 Domain + Infrastructure；App 是 `net8.0-windows` WinExe，测试项目引用不了。表情映射是纯数据与纯函数，放 Domain 才能单测，也符合「领域算法与 UI 解耦」的项目约束。

**2. 坐标系统一改成设计稿的 120×120，不做 64→120 的换算。**
设计稿所有形变数值（`scaleY(.08)`、`translate(-3.5px,-1px)`、`rotate(-8deg)`）都基于 `viewBox 120`。若保留 64 坐标系再逐项折算，19 条预设会变成 19 组「近似值」，以后对照设计稿永远对不上。直接重排 XAML，数值一一照抄。

**3. 稳态与瞬态分离。**
稳态（idle/focus/soon/done/late/break/sleepy/love…）由状态机算，持续到信号变化；瞬态（blink/wander/wink/laugh/surprise）是插播，有固定时长，播完必须回退。两者混成一个枚举会让「laugh 播完该回到什么」变成隐式约定。

**4. 回退目标是「重新解析的当前稳态」，不是「播放前的快照」。**
瞬态可能持续 1.2 秒，期间课程状态完全可能从 soon 变成 focus。若回退到快照，会短暂闪回过期表情。

**5. 弹簧曲线用 `KeySpline` 实现，`DoubleAnimation` 做不到。**
设计稿是 `cubic-bezier(.34,1.15,.5,1)`；WPF 的 `DoubleAnimation` 只有 `IEasingFunction`（幂函数/回弹/弹性），没有贝塞尔。落法是 `DoubleAnimationUsingKeyFrames` + 单个 `SplineDoubleKeyFrame{ KeySpline = new KeySpline(0.34, 1.15, 0.5, 1) }`。`y > 1` 的控制点表示过冲，`KeySpline` 支持，这正是「一次到位、轻微回弹」的来源。

## 五、数据模型骨架

```csharp
namespace FuShi.Domain.Assistant;

/// <summary>黑团子的 19 种情绪。顺序与设计稿分组一致，便于对照。</summary>
public enum BotExpression
{
    // 常驻
    Idle, Blink, Wander, Sleepy,
    // 课程
    Focus, Soon, Done, Late, Break,
    // 社交
    Happy, Laugh, Wink, Love, Smug, Shy,
    // 情绪
    Sad, Angry, Surprise, Dizzy,
}

/// <summary>脸上出现的形状层：椭圆眼及其四种替代形状。</summary>
public enum EyeShape
{
    Oval,        // 竖椭圆（默认）
    Arc,         // 上弧（happy / done）
    ArcDeep,     // 更弯的上弧（laugh）
    Circle,      // 圆睁（surprise）
    Cross,       // 两枚 X（dizzy）
    Exclamation, // 感叹号（late）
    Heart,       // 心形（love）
}

/// <summary>眼睛光色。除 love 外，光色只表达状态。</summary>
public enum GlowTone { Ice, Amber, Mint, Coral, Rose }

/// <summary>单只眼的形变，数值直接对应设计稿 CSS 的 transform。</summary>
public readonly record struct EyeDeformation(
    double ScaleX = 1, double ScaleY = 1,
    double TranslateX = 0, double TranslateY = 0,
    double RotateDegrees = 0);

/// <summary>一种情绪的全部渲染参数。</summary>
public sealed record BotExpressionPreset(
    BotExpression Expression,
    EyeShape Shape,
    EyeDeformation Left,
    EyeDeformation Right,
    GlowTone Glow,
    bool IsTransient,
    int HoldMilliseconds);
```

`BotSignals` 只承载**事实**，不承载判断：

```csharp
public readonly record struct BotSignals(
    bool InClass,
    OccurrenceStatus? CurrentStatus,
    int? MinutesUntilNext,
    int? MinutesSinceLastEnd,
    bool HasConflict,
    bool AllDoneToday,
    TimeSpan IdleFor);
```

`BotExpressionDirector` 的优先级固定为：

```
1. 当前课存在
   1.1 Status == Done                              → Done
   1.2 Status == Missed，或 Fired 且已过开始时刻   → Late
   1.3 其余（InProgress / Pending）                → Focus
2. 下一节进入提前量窗口                              → Soon
3. 刚下课 ≤ BREAK_WINDOW 且今天还有后续              → Break
4. 长期未交互 ≥ SLEEPY_AFTER                        → Sleepy
5. 其余                                             → Idle
```

「当前课进行中却 2 小时没交互」显示 Focus 而不是 Sleepy：Sleepy 是待机氛围，不能覆盖正在发生的课程。

## 七、课程场景接入表

设计稿第 03 节的 9 条，落到代码里的判定口径：

| 场景 | 触发 | 表情 | 代码判定 |
|---|---|---|---|
| 空闲常驻 | 无任务 | idle + 插播 blink/wander | 无当前课、无临期 |
| 开课强提醒 | 课前 5 分钟 | soon | `MinutesUntilNext ≤ 提前量`；提前量取设置里的 `LeadTimeMinutes`（默认 5），为 0 时本档不出现，保持与提醒一致 |
| 专注时段 | 课程进行中 | focus | `CurrentStatus == InProgress` |
| 完成打卡 | 任务结束 | done | `CurrentStatus == Done`；整日全部完成时插播一次 `laugh`（需 ≥ 3 节） |
| 超时未响应 | 打卡逾期 | late | `CurrentStatus == Missed`，或 `Fired` 且已过 `StartsAt` |
| 课间休息 | 番茄钟间歇 | break | 无当前课、刚下课 ≤ 10 分钟且今天还有后续 |
| 日程冲突 | 两课时间重叠 | surprise | 同一天相邻时段 `next.StartsAt < current.EndsAt`；上升沿触发一次 |
| 长期未交互 | > 2 小时 | sleepy | 无课程信号时 `IdleFor ≥ 2h` |
| 彩蛋 | 连续 7 天全勤 | love | `BotSignals.AllDoneForSevenDays`，依赖 M4b 的统计结果；M4b 未完成前恒为 false |

未接入的 happy / love / smug / shy / sad / angry / dizzy 保留在预设表：它们的形状与光色有单测覆盖，将来接互动反馈时只需加一条映射，不碰 UI。

## 八、动效与常量

| 常量 | 值 | 来源 |
|---|---|---|
| `STEADY_TRANSITION_MS` | 320 | 设计稿「260–420ms」取中值；低于 260ms 过冲像抽一下，高于 420ms 在 focus↔break 高频切换时显拖 |
| `TRANSIENT_RETURN_MS` | 260 | 瞬态回落要利落，不占满 420 |
| `GLOW_TRANSITION_MS` | 180 | 设计稿「光色 180ms」 |
| `BLINK_INTERVAL_MIN/MAX_MS` | 4000 / 6000 | 设计稿「每 4–6s 一次」 |
| `BLINK_CLOSE_MS / BLINK_OPEN_MS` | 70 / 100 | 沿用现有实现，收敛总时长到设计稿的 80ms 闭眼区间 |
| `WANDER_INTERVAL_MIN/MAX_MS` | 25000 / 40000 | 设计稿「25–40s」 |
| `WANDER_OUT_MS / WANDER_BACK_MS` | 240 / 420 | 现有实现，符合设计稿「缓慢看一眼再回来」 |
| `BREAK_WINDOW_MINUTES` | 10 | 「刚下课」的口径 |
| `SLEEPY_AFTER` | 2 小时 | 设计稿「> 2 小时」 |

常驻插播只发生在 `Idle` 稳态：`Focus / Soon / Late / Done / Break` 一律不眨眼不张望（设计稿的演示脚本也只在 idle 时插播）。`Sleepy` 本身已经是「眼睑垂一半」，再插眨眼会自相矛盾。

`reduced-motion` 的 WPF 等价物是 `SystemParameters.ClientAreaAnimation`：
- 为 false 时：不启动常驻 blink/wander、不接受瞬态、稳态切换用 0ms 直接到位；
- 监听 `SystemParameters.StaticPropertyChanged`，用户在系统里开关「动画效果」后立即生效。

## 九、瞬态播放器

规则收敛在 `BotView` 内部，对外只暴露两个依赖属性：

```xml
<local:BotView Expression="{Binding Expression}"
                TransientExpression="{Binding TransientExpression}"
                TransientSequence="{Binding TransientSequence}" />
```

- `Expression`：稳态，状态机算出来的。
- `TransientExpression` + `TransientSequence`：瞬态请求。序号自增用于「同一情绪连续播放两次」也能重新触发（依赖属性值没变不会走 `OnPropertyChanged`）。

播放器行为：
1. 新瞬态到来时打断旧的，从头播新的；
2. 播放期间只改眼形与形变，不改光色（瞬态不携带新光色）；
3. 到 `HoldMilliseconds` 后，读**当前** `Expression` 回落，回落用 260ms；
4. 常驻 blink/wander 与外部瞬态共用同一个「正在播放」槽位，避免两套动画同时改同一组变换。

## 十、状态管理与组件编排

```
ReminderEngine ──ScheduleChanged──▶ App.ReloadWidget
                                      │
                                      ▼
                            WidgetWindow.ApplySchedule(slots)
                                      │
                                      ▼
                         WidgetViewModel.Refresh(now)   ←── DispatcherTimer 每秒
                                      │
              ┌───────────────────────┼────────────────────────┐
              ▼                       ▼                        ▼
     BuildSignals()          BotExpressionDirector      Pulse 上升沿检测
     （纯取数）                  .ResolveSteady            （冲突 / 全勤）
              │                       │                        │
              └───────────────────────┴────────────┬───────────┘
                                                   ▼
                                        Expression / Pulse 属性
                                                   │ 绑定
                                                   ▼
                                         BotView（动画 + 瞬态播放器）
```

- 状态仍然只有一份：`WidgetViewModel` 每秒在缓存的 `_slots` 上算，不打数据库，不新增计时器。
- 交互时间戳（`IdleFor` 的依据）由视图在鼠标进入、拖动、双击打开课表时推给 VM；不引入全局钩子。
- 冲突与全勤用 latch：条件从 false 变 true 时发一次 `Pulse`，条件消失后复位，避免每秒重播。
- 跨天复位：`AllDoneToday` 与「今日已庆祝」的标记都按 `DateOnly` 比较，零点自然失效。

## 十三、风险与对策

| 风险 | 对策 |
|---|---|
| `KeySpline` 过冲导致眼睛越出壳体或出现异常尺寸 | 过冲只作用于缩放/位移，壳体不参与动画；`soon` 的 1.1 倍在 44px 下约 +2px，安全 |
| 每帧改 `DropShadowEffect.Color` 触发重绘 | 光色只在状态切换时动画 180ms，静止期不写属性；眼睛与光晕共用一个颜色源 |
| 共享资源画刷被 WPF 冻结，无法做 `ColorAnimation` | 眼睛画刷、光晕画刷在 `BotView` 构造时用代码创建并持有实例，不放进 `Resources` 让 BAML 优化冻结 |
| 常驻动画与瞬态抢同一组 `Transform` | 统一由一个播放槽位驱动，常驻插播也走瞬态通道 |
| 多个 `BotView` 实例各自计时器 | M4.5 只挂悬浮窗一个实例；将来主窗口要用时改为「一个播放器驱动多视图」 |
| 跨天/跨午夜导致全勤 latch 不重置 | 标记按 `DateOnly` 存，日期变化即失效 |
| 提前量为 0 的用户看不到 soon | 与提醒语义保持一致，文档写明；需要的话由用户在设置里调大提前量 |
| 120 坐标系缩到 44px 后光晕变细 | `Viewbox` 缩放对矢量有效；实机对照设计稿截图，必要时单独调 `BlurRadius` |
| 删除 `BotMood` 影响其它调用方 | 已全仓 grep：只有 `BotView` 自身与 `WidgetWindow.xaml` 的 `Mood="Idle"` 两处，可安全删除 |

### M4.5b（2026-10-21）

**落地**

- `BotView.xaml` 重写为设计稿的 120×120 坐标系：壳体用一条 `PathGeometry` 表达 `rect 14,38,92×48 rx24`（rx 恰为半高，路径退化成两头半圆的胶囊，与设计稿完全等价）；底部投影、壳体亮面渐变、壳内四层高光全部按设计稿的椭圆与模糊半径复刻。

- 瞬态播放器统一由「正在播放」槽位驱动：常驻眨眼（4–6s）、张望（25–40s）与外部插播共用一套通道；回落读**当时**的 `Expression`。眨眼/俏皮的进场与回落 70/100ms、张望 240/420ms、其余 320/260ms。

**视觉验收中发现并修掉的两个问题**

2. 瞬态进场走了完整的 `ApplyPreset`，会把光色一并刷成冰白，与第九节「播放期间只改眼形与形变，不改光色」冲突——琥珀临期时眨一下眼会闪一下白色。给 `ApplyPreset` 加 `changeGlow` 参数，瞬态传 `false`，光色沿用稳态。
