# M3.5 主窗口视觉实施计划

> 依据：`浮时-主窗口视觉稿.html`（2026-10-21 定稿，用户整体认可）
> 前置：M3（课表 / 设置）已完成；M3.5 只做视觉与主题，不改任何业务行为。

---

## 1. 当前阶段与目标

| 项 | 内容 |
| --- | --- |
| 阶段 | M3 与 M4 之间的视觉补齐（记为 M3.5） |
| 目标 | 把主窗口从「功能可用」提升到「视觉定稿」，并建立明 / 暗双主题令牌体系 |
| 不做 | 事项页、统计页、阶段切换器的真实交互（均属 M4）；调度、通知、数据库逻辑零改动 |
| 验收基线 | 视觉稿的三个视图（明 / 暗 / 双主题对照）在真实 WPF 窗口里 1:1 复现 |

**为什么单独立阶段：** 当前 WPF 实现与设计稿有 5 处结构性偏差（科目色铺满整格、强调色与首个科目色撞色、无间距/圆角/字阶令牌、系统默认标题栏、两份设计文档的视觉规范互相矛盾）。这些不是「调一下颜色」能解决的，必须先立令牌体系，否则后续每个界面都会再长出第三套写法。

## 3. 技术选型与理由

### 3.1 玻璃：实色拟玻璃（已确认）

不使用 `AllowsTransparency="True"`（会禁用硬件加速、丢失系统投影），也不调用 `SetWindowCompositionAttribute` / `DwmSetWindowAttribute(SYSTEMBACKDROP_TYPE)`。

理由：设计稿的「玻璃」由四层构成——底色 tint、顶部镜面高光、噪点、渐变描边。真正的背景模糊只贡献其中一层，却要付出跨版本兼容与拖动掉帧的代价。实色版本在 Win10 / Win11 上完全一致，且 WPF 能精确表达其余三层。

### 3.2 无边框窗口

`WindowStyle="None"` + `WindowChrome`（`CaptionHeight=44`、`ResizeBorderThickness=6`、`UseAeroCaptionButtons=False`）。窗口按钮单独绘制，`WindowChrome.IsHitTestVisibleInChrome="True"`。

不自绘外投影：`WindowChrome` 下窗口外的区域不归 WPF 绘制，稿子里的三层外投影由 DWM 提供一层系统影，内部再叠接触影与内高光。这是与设计稿唯一无法 1:1 的项，已在风险表登记。

Win11 圆角：`DwmSetWindowAttribute(hwnd, DWMWA_WINDOW_CORNER_PREFERENCE=33, DWMWCP_ROUND=2)`。Win10 不生效，退化为直角外框（内部圆角容器仍然存在），可接受。

### 3.3 令牌：`ResourceDictionary` 分三份

- `Shared.xaml`：不随主题变化的结构值。
- `Light.xaml` / `Dark.xaml`：键集合必须完全一致，只有值不同。
- `Controls.xaml`：样式只引用键名，不写具体颜色。

`App.xaml` 里合并顺序固定为 `Shared → 主题槽位 → Controls`，`ThemeService` 只替换中间那一个字典实例，索引恒定，避免「越换越多」。

### 3.4 主题切换：即时生效

`ThemeService.Apply(theme)` 在 `Application.Current.Resources.MergedDictionaries` 的固定索引处替换字典。所有界面引用一律 `DynamicResource`，WPF 会自动重解析，窗口不重建、状态不丢。

`StaticResource` 在加载时求值，切换后不会更新——这是本轮最大的机械性风险，见 §7 对策。

### 3.5 科目染色：用 `Opacity`，不用带 alpha 的颜色

WPF 的 `SolidColorBrush` 颜色是静态的，主题切换不会重算 alpha；若在 ViewModel 里生成带 alpha 的 Brush，就必须在切主题时刷新 42 个格子的绑定。

改为：ViewModel 只提供**满色**的 `SubjectBrush`；单元格内叠一个底色 `Border`，其 `Opacity="{DynamicResource ChipTintOpacity}"`。切换主题时只有那个 double 变，格子自动跟着变，零刷新、零事件。

### 3.6 不引入第三方 UI 库

HandyControl / MaterialDesignInXaml 自带主题体系，与本稿的定制质感冲突，改造它们的模板比自建两套字典更贵。两套字典合计约 220 行。

## 4. 实现策略

### 4.1 令牌分层

```
Shared.xaml        间距 / 字号 / 行高 / 动效时长 / 字体族 / 控件高度
   ↓
Light.xaml 或 Dark.xaml   画刷 / 颜色 / 透明度 / 窗口与卡片圆角 / 噪点强度
   ↓
Controls.xaml      主按钮、分段控件、输入框、窗口按钮、滚动条
```

### 4.2 单元格的四层结构

```
Grid（单元格）
├─ Border  底色染色层   Background=SubjectBrush   Opacity={DynamicResource ChipTintOpacity}
├─ Border  左色条       Width=2.5  Background=SubjectBrush  Opacity={DynamicResource SubjectBarOpacity}
├─ StackPanel 内容      科名 14 / 备注 11.5 / 角标 10
└─ Border  当前环       BorderBrush={DynamicResource CurrentRingBrush}  BorderThickness=1
```

- 空格：以上四层全部不显示，只有 hover 时出现淡底与「+」。
- 已跳过：内容层整体 `Opacity=0.62`，科名加删除线，角标保留。
- hover：染色层 Opacity 切到 `ChipTintOpacityHover`，色条提到 1.0（`Style.Triggers` + `DynamicResource` setter）。

### 4.3 今日列车道

设计稿里是一条贯穿表头的淡色竖带。WPF 侧不重构成单一 Grid（会牵动行高自适应），而是在网格外层放一个 `Border`，由 `WeekGridView.xaml.cs` 在 `SizeChanged` 与数据重载后按真实列宽测量定位。

测量口径：取首行第 3 个日列单元格的 `ActualWidth` 与相对网格的 `TranslatePoint`，高度取首行顶到末行底。窗口隐藏时尺寸为 0，`IsVisibleChanged` 时补算一次。

### 4.4 标题栏

44px 高，左侧品牌点 + 「浮时」，中部 `Drag` 区，右侧最小化 / 最大化 / 关闭。三个按钮走 `SystemCommands.*Command`，最大化按钮图标随 `WindowState` 切换；关闭按钮 hover 变 `#DC4346`（不随主题变化，系统级约定）。

### 4.5 字号与渲染

统一 `UseLayoutRounding=True`、`TextOptions.TextFormattingMode=Display`、`TextRenderingMode=ClearType`。小字号（10/11.5）在 125% / 150% 缩放下最容易发虚，这两项是硬要求，不是优化项。

## 5. 状态管理

| 状态 | 归属 | 读写规则 |
| --- | --- | --- |
| 当前主题 | `AppSetting.Theme`（单行表，已有字段） | 唯一写入方是 `SettingsViewModel.SaveAsync`；启动时由 `App.OnStartup` 读取 |
| 生效中的字典 | `ThemeService` 私有字段 | 只由 `Apply` 改；替换索引固定为 1 |
| 悬浮窗不透明度 | `AppSetting.Opacity` | 维持现有增量写入方式，主题不参与 |
| 科目颜色 | `SubjectPalette`（静态） | 与主题无关；主题只影响覆盖率 |

主题切换流程：

```
SettingsView 下拉变更
  → SettingsViewModel 调注入的 applyTheme 回调
  → ThemeService.Apply(theme)
  → 替换 MergedDictionaries[1]
  → DynamicResource 全部重解析（主窗口 / 悬浮窗 / 对话框同时变）
  → 保存 AppSetting.Theme（与现有 SaveAsync 同一次写入）
```

## 6. 启动时序

```
App.OnStartup
  → 建日志 → 单实例互斥 → BuildHost → InitializeDatabase
  → 读 AppSetting（含 Theme）
  → ThemeService.Apply(Theme)      ← 必须早于任何窗口创建
  → CreateTray → CreateWidget → CreateMainWindow（惰性，首次打开时）
```

主题必须先于窗口创建：`StaticResource` 之外，`FindResource` 取托盘资源也走合并字典，晚于窗口创建会导致首帧用错主题再闪一下。

## 7. 风险与对策

| # | 风险 | 表现 | 对策 |
| --- | --- | --- | --- |
| 1 | 漏改 `StaticResource` | 切主题只变一半，重启才正常 | 改完执行全仓 `StaticResource` 审计；令牌类资源一律 `DynamicResource`；验收时每个页面各切一次 |
| 2 | 最大化时窗口溢出屏幕 | 边缘被裁 8px、标题栏跑到屏幕外 | `WindowChrome` + 监听 `WM_GETMINMAXINFO` 修正；100% / 150% / 200% DPI 各验一次 |
| 3 | Win10 直角外框 | 外框方、内部圆角 | 接受；Win10 不调用圆角 API，不做假圆角蒙层 |
| 4 | 两套字典键漂移 | 某控件在暗色下取不到值，静默用默认色 | `ThemeService` 启动时比对键集合，缺失即 `Debug.Fail` 并写日志 |
| 5 | 噪点贴图在缩放下摩尔纹 | 细密闪烁 | 128px 平铺、强度 ≤3.5%；在 125% 缩放下目检 |
| 6 | 单元格多层 Border 带来的性能 | 42 格 × 4 层 | 不用 `Effect`（投影）逐格渲染；hover 只改 Opacity |
| 7 | 主题切换影响悬浮窗 | 悬浮窗与主窗口不同色 | 悬浮窗只迁移键名、不改结构；切主题后目检其展开/收起两态 |
| 8 | 科目色与强调色再次撞色 | 绿格子里看不出「当前」 | 调色板去掉橙红，首个科目改为湖蓝；当前格靠环 + 白片区分 |
| 9 | 圆角容器裁剪不掉子元素 | 网格行线顶到圆角处 | 内容区统一内边距 ≥18；标题栏与状态栏自带圆角背景 |

### 3.7 不透明窗口里的 alpha：主窗口需要一份「实色」表面

`SurfaceBrush` 带 alpha（`#C215151B`），这是给悬浮组件的 layered window 用的——那里 alpha 真的会透出桌面。
主窗口不是 `AllowsTransparency`，WPF 会把半透明背景合成到黑色上：`#C215151B` 实际渲染成 `#101014`，比设计稿更暗。

因此主窗口使用新增的 `WindowSurfaceBrush`（明 `#F7F7F8` / 暗 `#17171D`，不带 alpha），
`SurfaceBrush` 继续留给悬浮组件。这一项在第 3 步落地标题栏时一起做。

### 3.8 键名保持现状（与初版计划不同）

初版 §8.5 打算把 `SurfaceBrush / LabelBrush …` 重命名为语义化键名。实施时放弃：
35 处引用要全量改名，收益只是可读性，却把真正的风险（`StaticResource` 漏改）埋进更大的 diff 里。
最终保留既有键名，只把「值」按主题分层，并用新增键承载新概念（`ChipTintOpacity`、`TodayWashBrush` 等）。

## 9. 验收标准

1. 构建 0 警告 0 错误；`dotnet test` 全绿（现有 90 项不得回归）。
2. 明 / 暗两主题下，主窗口与视觉稿逐项对齐：窗口圆角、1px 渐变描边、顶部高光、噪点、今日列车道、当前格、跳过态、分段控件、主按钮。
3. 设置页切换主题后**无需重启**，主窗口、悬浮窗、对话框同时变化，且窗口不重建、当前页签与滚动位置不丢。
4. 三档 DPI（100% / 150% / 200%）下无文字截断、无布局错位；125% 下噪点无肉眼摩尔纹。
5. 无边框窗口可拖动、可双击标题栏最大化、可四边缩放；最大化不溢出工作区。
6. 全仓 `StaticResource` 审计：令牌类资源零残留。
7. 主题字典键一致性自检在启动时通过。

第 6 步（悬浮窗与对话框）：

- **显式 Style 会顶掉隐式 Style（本轮最隐蔽的坑）**：设置页与两个编辑对话框原先用 `FormField`（`TargetType=Control`、无 `BasedOn`）套 ComboBox，导致 `Controls.xaml` 的主题化模板失效、静默回落到 Aero2 白底模板。改为 `FormCombo` / `FormText`，用 `BasedOn="{StaticResource {x:Type ComboBox}}"` 继承 App 级隐式样式，只补外层 `Margin`。不报错、不抛异常，只是外观悄悄换回系统默认——这类问题只能靠实机截图发现。
- **对话框系统标题栏**：保留原生标题栏的对话框在暗色下会露出白色标题栏。`WindowChromeHelper.TryApplyCaptionTheme` 走 `DwmSetWindowAttribute(DWMWA_USE_IMMERSIVE_DARK_MODE = 20)`，在 `SourceInitialized`（句柄就绪）后应用；Win10 20H1 以下调用失败返回 `false`，不抛异常。
- **时区下拉空白（第 3 步遗留待查项）**：根因是 `TimeZoneInfo.GetSystemTimeZones()` 在 Windows 返回 `GMT Standard Time` 这类 Windows ID，而库里存 `Europe/London` 这类 IANA ID，选中项不在候选集里就显示空白。新增领域层 `TimeZoneOptionBuilder.Build(defaultId)`：系统时区去重后把默认 IANA Id 置顶；`SettingsViewModel.TimezoneOptions` 只负责包成 `ObservableCollection`。配 4 个单测（置顶、不重复、不丢系统项、系统枚举缺失时仍追加默认项）。
- **实测**：设置页与新建时段对话框明/暗均确认，新建科目对话框确认亮色；ComboBox / TextBox / CheckBox / Slider / 滚动条 / 按钮全部走主题化模板，时区下拉显示 `Europe/London`。悬浮窗折叠态明/暗均确认；展开态因自动化输入（`SetCursorPos` 不触发 WPF 鼠标跟踪）无法稳定截取，留待人工目检。
