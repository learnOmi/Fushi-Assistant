## 三、数据与迁移

### 3.1 表结构

现有 8 张表已经覆盖 M4 的全部实体，**不新增表**。只有一处建议加列：

**`CompletionLog.SubjectId`（可空，快照列）**

- 现状：`CompletionLog` 只有 `EntryId`，统计按科目聚合只能 join `ScheduleEntries`。
- 问题：条目被删后历史记录 join 不到；用户改条目科目后，历史统计会被"追溯改写"。
- 方案对比：

| 方案 | 优点 | 代价 |
|---|---|---|
| **A. 加 `SubjectId` 快照（推荐）** | 历史统计稳定，删除/改科目都不影响过去 | 一次迁移 + 旧数据回填 |
| B. 靠 `EntryId` join | 零迁移 | 删条目丢统计、改科目改写历史 |
| C. 加 `SubjectName` 文本快照 | 抗删除最彻底 | 冗余、科目改名后历史显示旧名 |

选 A：迁移只加一个 nullable 列与 `(Date)`、`(SubjectId)` 两个索引；旧数据用一次 `UPDATE ... FROM ScheduleEntries` 回填，回填失败的留 `NULL`，统计里归为「未分类」。

### 3.2 事项的重复表示

`TaskItem.RepeatRule` 是字符串，原注释写的是"RRULE 风格"。M4 不引第三方解析器，先把它当**受控枚举文本**用：`NONE`（一次性）、`DAILY`、`WEEKLY`。

- 选这个的原因：事项页是 Should 级，M4 的验收重点是"能建、能提醒、能完成"，不是日历级重复规则。
- 字段仍是字符串，将来要升级成真 RRULE 时不需要改表，只换解析器。

### 3.3 事项提醒复用现有账本

不新建调度器。事项按 `DueAt` + 重复规则展开成 `Occurrence`，用 `SourceType = Task` 与课表实例区分：

- 唯一键 `(SourceType, SourceId, PlannedAt)` 天然保证"同一事项同一时刻不重复弹"。
- 补偿扫描、系统唤醒、静默时段、强/弱提醒全部复用 `ReminderEngine`，不复制一份。
- 代价：`RecurrenceExpander` 目前只认 `ScheduleEntry`，需要新增 `TaskRecurrenceExpander`（纯函数、可单测）。

## 五、子阶段步骤与验收

### M4a 阶段管理

1. `PhaseService`：列表、创建、重命名、`ActivateAsync(id)`、删除。唯一生效用一次事务完成：先把其余 `IsActive` 置 false，再把目标置 true。删除时若存在 `CompletionLog` 引用其条目，拒绝硬删并提示改用归档。
2. 顶部阶段徽标变为可点击：下拉列出全部阶段 + 「管理阶段…」。切换后立即刷新周网格。
3. 切换收口：`ReconcileAllAsync(now)` → `ReminderEngine.RequestRescan()` → `reloadWidget()` → 重载网格。顺序必须是"先删旧实例、再唤醒引擎"，避免旧阶段提醒在切换瞬间弹出。
4. 保留 `EnsureActivePhaseAsync` 作为兜底：任何路径把生效阶段删空后，下次载入自动重建「默认课表」。
5. 测试：只能有一个生效阶段；切换后旧阶段未来实例被清、新阶段实例被展开；历史 `CompletionLog` 不受影响。

**验收**：新建「实习期」→ 切换 → 网格立即变成新阶段课表 → 悬浮窗下一节课跟着换 → 切回默认课表，行为对称。

### M4b 统计页

1. 迁移加 `CompletionLog.SubjectId` 并回填；`ReminderResponseService` 写日志时带上当时的 `SubjectId`。
2. `StatisticsService.GetAsync(from, to)` 返回：计划分钟、实际分钟、完成/跳过/错过计数、按时段分布、按科目分布。
3. `StatsView`：区间（本周 / 本月 / 自定义）、三张数字卡、科目横条（科目色 + 占比）、最近 7 天完成率。
4. 空数据不显示 0 值图表，给「还没有完成记录」的空态。
5. 测试：聚合边界（起止日含）、跨科目、`SubjectId` 为 NULL 归「未分类」。

**验收**：M3 已积累的完成记录能直接出图；删掉一条课表后，历史统计数字不变。

### M4c 事项页

1. `TaskService`：CRUD、`MarkDone/Skip`、按区间取列表；写操作后对账该事项的未来实例。
2. `ItemsView`：按日期分组，显示标题、截止、优先级、状态；点击行开编辑；「+ 添加事项」。
3. `TaskRecurrenceExpander`：`NONE` 在 `DueAt` 当天出一次；`DAILY/WEEKLY` 在 7 天视野内按天/周重复。截止为空的一次性事项只显示不提醒。
4. 提醒：`ReminderRuleResolver` 优先取该事项的规则，没有则用全局提前量；强度沿用现有双通道口径（Soft 只记日志，Strong 弹窗 + Toast）。
5. 事项与课表实例共用 `Occurrence` 账本，唯一键已能防重；补偿扫描无需新逻辑。
6. 测试：三档重复展开、修改 `DueAt` 后旧未来实例被清、完成/跳过后不再提醒。

**验收**：新建「明天 09:00 交作业」→ 到点前按提前量提醒 → 点完成后统计页计入 → 列表状态变 Done。

### M4d 发布收尾

1. `AutostartService`：写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\FuShi`，值为带引号的 exe 全路径；关闭时删值。**先落库再写注册表**，写失败回滚开关并提示，不静默失败。
2. 启动时校验注册表值与当前 exe 路径；不一致（用户移动了程序）则重写或提示。
3. 发布：`dotnet publish -c Release -r win-x64 --self-contained` 单文件 + 便携 zip；数据库与日志仍在 `%APPDATA%\FuShi`，不随安装目录迁移。
4. 多屏/DPI：应用清单启用 PerMonitorV2；悬浮窗位置读取时夹到虚拟屏幕范围，避免拔掉副屏后窗口跑到屏幕外。
5. M3.5 尾巴：人工确认悬浮窗展开态明暗；删除无引用的 `UiConstants.GRID_CELL_CORNER_RADIUS`。

**验收**：重启系统后自动出现在托盘；把发布目录改名后启动，自启项被纠正；双屏拔插后悬浮窗仍在可见区域。

## 六、状态管理与一致性

- 所有写操作继续走 `AddDbContextFactory` 的短生命周期上下文；不引入长事务跨 UI 等待。
- 阶段切换是一个事务内的状态翻转，事务外依次做对账、唤醒、刷新；任一步失败只记日志并把 UI 回读为库中真实状态，不回滚已提交的阶段。
- 事项与课表的"改动后收口"共用同一个模式：`对账(涉及 Id) → RequestRescan → reloadWidget → 重载视图`；不复制粘贴。
- 统计是只读查询，不做缓存；个人数据量级下每次进页重算比维护失效逻辑更可靠。
- 自启是"数据库状态 + 注册表副作用"两处状态：以数据库为准，启动时校正注册表。

### 11.2 关键决策与理由

1. **新建阶段不自动生效**：生效只有 `ActivateAsync` 一个入口，避免"建着建着课表就换了"。首个阶段仍由 `EnsureActivePhaseAsync` 兜底创建。
2. **切换 = 一次事务翻两列**：先把其余 `IsActive` 置 false，再把目标置 true，避免出现"两个阶段同时生效"的中间态被引擎读到。
3. **全量对账与局部对账分开**：`ReconcileAsync(ids)` 只处理编辑涉及条目；新增 `ReconcileAllAsync()` 因阶段切换会整体换课表，必须整片重建。两者的删除口径一致（未来 Pending 或已顺延 Pending），历史状态不动。
4. **收口顺序固定**：`ReconcileAllAsync → RequestRescan → reloadWidget → 重载网格`。反序会让引擎在旧实例尚未清除时先扫到旧阶段提醒。
5. **删除期间保留历史**：删除阶段会级联删课表条目，但 `Occurrence` 与 `CompletionLog` 不删；已发生的历史记录保留归属。有完成记录的阶段直接拒绝硬删，提示"已有完成记录"。
6. **对话框用 `HasChanges` 当 DialogResult**：阶段管理没有"确定/取消"草稿态，操作即时生效；只把"是否改过"带回去，调用方据此决定是否全量重排。点 X 与点「关闭」同一口径。
7. **徽标下拉在代码后置动态构建**：`ContextMenu` 的 `Items` 与 `ItemsSource` 互斥，而菜单既要列全部阶段又要固定「管理阶段…」，动态构建最简单可靠；`StaysOpen=false` 避免菜单残留（沿用 M3 托盘菜单的教训）。

### 12.2 关键决策与理由

1. **快照列不建外键**：`CompletionLog.SubjectId` 只存「当时是谁」，科目被删也不级联、不置空。外键会把「删科目」变成一个影响历史统计的操作，与「历史不可追溯改写」的目标相反。
2. **回填只在条目仍存在时发生**：旧记录靠 `EntryId` 回查科目，条目已被删的行没有可靠来源，留 NULL 归「未分类」；回填失败不影响启动，也不触发删库重建。
3. **未分类合并成一个桶**：`NULL` 快照与「科目已删除」在分组前统一解析为 null，避免界面上出现两行同名的「未分类」。
4. **聚合只在服务层算一次**：完成率、占比、最近 7 天全部由 `StatisticsService` 产出，视图模型只做「数字 → 文案」「百分比 → 星号权重」。两处各算一遍必然漂移。
5. **最近 7 天含今天且固定 7 格**：窗口取「今天往前 6 天 ~ 今天」，无记录的日子保留一行显示破折号，柱子数量不随数据跳动；`today` 由调用方传入，服务内部不读时钟，便于单测。
6. **自定义区间用文本框而不是 DatePicker**：现有主题没有覆盖 `DatePicker` 的日历弹层，深色下会露出一块白底；两个 `yyyy-MM-dd` 输入框 + 就地校验更符合当前控件体系，也不引入新样式债。
7. **统计页签选中时重算**：只读、无缓存；个人数据量级下每次进页重算，比维护「何时失效」更可靠。窗口载入时也刷新一次，避免首次进入统计页看到空值。
8. **图表用原生控件**：科目分布是「两列星号 + 圆角 Border」，最近 7 天是「两行星号 + 柱状 Border」，零依赖且随窗口宽度自适应。
