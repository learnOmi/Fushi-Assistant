## 二、M5a 数据安全

### 2.1 备份

新增 `FuShi.Infrastructure/Data/BackupService.cs`：

- **快照方式**：`VACUUM INTO '目标路径'`。选它而不是文件复制：DELETE 日志模式下强杀会残留 `-journal`，直接拷贝可能拿到不一致的页；`VACUUM INTO` 在 SQLite 内部生成一致性快照，且产物是单个文件，便于用户拿走。
- **每日自动备份**：`backups/fushi-YYYYMMDD.db`。同名已存在则跳过，保证一天一份、多次启动不重复。
- **手动备份**：`backups/fushi-manual-YYYYMMDD_HHmmss.db`，永不被自动清理。
- **保留策略**：只清理自动备份，按文件名倒序保留最近 7 份；手动备份不参与。
- **失败处理**：返回 `BackupResult(Success, FilePath, Error)`，不抛异常；启动时失败只记警告，不阻止启动。
- 路径常量集中在 `BackupConstants`：`BACKUP_FOLDER_NAME`、`AUTO_FILE_PREFIX`、`MANUAL_FILE_PREFIX`、`AUTO_RETAIN_COUNT`、日期格式。

### 2.2 CSV 导出

新增 `FuShi.Infrastructure/Data/ExportService.cs`：

- 导出到 `%APPDATA%\FuShi\export\`：
  - `schedule-YYYYMMDD_HHmmss.csv`：当前生效阶段的条目（周几、开始、结束、科目、类型、备注、是否启用）。
  - `tasks-YYYYMMDD_HHmmss.csv`：全部事项（标题、截止、优先级、重复规则、状态、备注）。
- 编码用 `UTF8Encoding(true)`（带 BOM），否则 Excel 打开中文乱码。
- CSV 转义：含逗号、双引号、换行的字段用双引号包裹，内部双引号翻倍；转义逻辑抽成可单测的纯函数。

### 2.3 设置页「数据与诊断」

在设置页保存按钮之前新增一节：

- 信息行：数据库路径、备份目录、上次备份时间、日志目录、版本号。
- 操作按钮：「打开数据目录」「立即备份」「导出 CSV」。
- 统一状态位：`StatusMessage`（成功，绿色）与 `StatusError`（失败，红色）。保存失败、备份失败、导出失败都显示在这里，不再只写日志。
- 现有 `AutostartError` 合并进 `StatusError`，避免两个错误位抢位置。

### 2.4 启动接线

`App.OnStartup` 在 `InitializeDatabase()` 之后调用 `CreateDailyIfNeeded()`，失败只记日志；随后照常创建主题、托盘、悬浮窗、引擎。

### 2.5 测试

- 备份文件确实生成、内容可打开、同一天第二次调用不覆盖。
- 保留策略只删自动备份、保留手动备份。
- CSV 转义：逗号 / 引号 / 换行 / 中文。
- 备份失败（目录不可写）返回失败而不是抛异常。

## 三、M5b 交互语义

### 3.1 事项提醒按钮

- `ReminderMessage` 增加 `IsTask` 字段，由 `ReminderEngine.FireAsync` 从 `PendingReminder` 带入。
- `ReminderPopupWindow`：`IsTask = true` 时主按钮文案改为「完成」，点击映射 `ReminderAction.Finish`；课表维持「开始」。
- 响应服务对 Task 的 `Finish` 走已有事项完成分支，不新增状态机。

### 3.2 重复事项「完成本次」

- 语义分档：
  - `RepeatRule = NONE`：完成 / 跳过 = 结束该事项（维持 M4c 行为），清未来实例。
  - `DAILY / WEEKLY`：完成 / 跳过只作用于**当次实例**——写 `CompletionLog`、把该 `Occurrence` 置终态，**不改 `TaskItem.Status`、不清未来实例**；下一日/下一周照常提醒。
- 结束系列只有一条入口：事项编辑器里的删除（已有二次确认）。
- 列表行状态显示改为「今日已完成 / 今日已跳过」，不再把系列任务整体标成 Done。

### 3.3 二次启动唤醒

- 主实例创建命名事件 `FuShi.Activate`，用 `ThreadPool.RegisterWaitForSingleObject` 等待；收到信号后在 Dispatcher 上 `Show + Activate` 主窗口（最小化则先还原）。
- 副实例拿不到互斥体时：`EventWaitHandle.OpenExisting("FuShi.Activate").Set()`，然后退出；拿不到事件（主实例尚未注册）仍按原逻辑静默退出。
- 退出流程释放事件与等待注册。

### 3.4 悬浮窗贴边吸附

- 拖动结束（`MouseUp`）时，若窗口边缘距当前工作区边缘 ≤ 16 px，吸附到该边缘。
- 吸附后照常 `PersistPosition`；启动恢复仍走已有的虚拟屏幕夹取。
- 吸附计算抽成纯函数，便于单测。

### 3.5 测试

- 重复事项完成一次后：未来 Pending 仍存在、任务仍 Active、日志 +1。
- 一次性事项完成后：未来 Pending 清空、任务状态 Done。
- 弹窗消息对事项带 `IsTask = true`。
- 吸附函数：四个方向、阈值内/外、跨屏坐标。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| `VACUUM INTO` 在旧 SQLite 版本不可用 | 目标库随 EF Core 提供，版本 ≥ 3.27；失败时降级为「跳过并记日志」，不阻塞启动 |
| 备份目录被安全软件拦截 | 与主库同盘同根，失败返回结果并在诊断区显示，不触发任何删库逻辑 |
| 重复事项语义改动影响统计 | 完成本次同样写 `CompletionLog`（SubjectId 为空），统计口径不变 |
| 唤醒事件跨会话/权限失败 | 全部包在 try/catch，失败退回静默退出，不影响主实例 |
| `ScheduleService` 拆分裂开同文件私有字段 | 只拆方法，字段与构造函数留在主文件；纯移动，测试作为回归网 |
| CI 在 Windows 上跑 WPF 构建失败 | 使用 `windows-latest` 并显式 `EnableWindowsTargeting`；先在本地模拟同一命令行 |
