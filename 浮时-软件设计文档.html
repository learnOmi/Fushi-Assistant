浮时 FloatTime · 软件设计文档

Windows 桌面悬浮课表提醒组件 · v1.0 设计基线 · 2026-10 · 纯设计阶段（未写代码）
产品定位：一个常驻 Windows 桌面的悬浮课表 + 提醒组件。它不是「课表 App」，而是一个行为触发器——核心价值在于「到点了会打断你」，而不是「给你看一张表」。这个定位决定了后续所有取舍。

2 · 数据模型设计

2.1 实体清单

实体作用关键字段
Phase 阶段课表的时间容器id, name, startDate, endDate, isActive
Subject 科目颜色 / 分类锚点id, name, color, category(study/work/life)
ScheduleEntry 课表条目周期性模板（非实例）id, phaseId, dayOfWeek, startTime, endTime, subjectId, note, enabled
Task 事项一次性 / 重复的杂乱提醒id, title, dueAt, repeatRule, priority, status
ReminderRule 提醒规则何时、以什么方式提醒id, ownerType, ownerId, triggerType, offsetMinutes, channels
Occurrence 提醒实例引擎的账本id, sourceType, sourceId, plannedAt, firedAt, status, snoozeUntil
CompletionLog 完成记录统计的原料id, date, entryId, plannedMin, actualMin, status
AppSetting 设置单行配置autostart, widgetPos, opacity, timezone, quietHours, leadTime, theme

2.2 关系

Phase 1 ──< N ScheduleEntry >── N ── 1 Subject
                     │
                     └──< N ReminderRule ──< N Occurrence
Task ──< N ReminderRule
ScheduleEntry ──< N CompletionLog（按日期展开）

2.3 三个关键设计决策

① 课表存「模板」，运行时展开成「实例」
ScheduleEntry 只存 dayOfWeek（周期模板），不存具体日期。触发时由引擎按日期展开成 Occurrence。
好处：改一次课表，全局立即生效；历史记录不受影响。
② Occurrence 是系统的核心表
它同时承担三件事：去重（已 fired 不再弹）、补偿（对比 plannedAt vs now，补发错过的）、统计（完成/跳过率）。
这张表设计得好不好，决定提醒引擎的可靠性。
③ 时间用「本地墙钟时间 + 时区字段」
不存 UTC 绝对时间戳。因为场景跨越英/中两地，且要处理英国夏令时切换——存本地时间更符合「课表」语义，避免 ±1 小时错位。

3 · 软件架构设计

3.1 架构风格

分层 + 模块化单体（Modular Monolith）。单机桌面应用不做微服务；内部严格分层，保证可测试、可替换。

3.2 分层结构

表现层 · Presentation4 个窗口
悬浮组件提醒弹窗主窗口托盘
▼绑定 / 命令
应用层 · Application核心：提醒引擎
Scheduler 调度课表服务事项服务统计服务
▼调用
领域层 · Domain纯规则，无依赖
重复规则展开去重算法错过补偿策略
▼读写
基础设施层 · Infrastructure外部依赖
SQLite 存储Windows 通知开机自启日志

提醒引擎（Scheduler）是唯一的核心模块：向上驱动 4 个窗口，向下依赖领域规则与 SQLite。价值是——将来换 UI 框架时，只需重写表现层，引擎与领域逻辑不动。

3.3 进程与线程模型

  • 单进程常驻（托盘存活），关闭主窗口不结束进程
  • 悬浮组件窗口：始终置顶、无边框
  • 主窗口：按需创建，关闭即隐藏（不销毁）
  • 提醒弹窗：触发时创建，自动消失
  • 调度器跑在后台线程，不阻塞 UI

3.4 核心：提醒引擎

启动 → 从 DB 载入未来 7 天 Occurrence → 装入内存最小堆
     → 定时器「睡到下一个触发点」（而非每秒轮询，省电）
     → 触发：写 Occurrence 状态 → 派发通知 → 刷新悬浮组件
     → 监听系统 resume 事件 → 做「错过补偿」扫描

取舍：不用 Windows 任务计划程序（不自持、难管理）；用内存调度 + 唤醒补偿（可控、可测、省电）。

3.5 架构决策记录（ADR）

编号决策理由
ADR-1单进程多窗口（非多进程）简单、内存可控、通信零成本
ADR-2内存调度 + 唤醒补偿（非 OS 调度）可控、支持动态课表
ADR-3SQLite（非 JSON 文件）需要查询/统计/事务，JSON 撑不住
ADR-4自绘弹窗 + 系统 Toast 双通道自绘有表现力；Toast 是免打扰时的保底
ADR-5课表模型 = 模板 + 实例见 2.3 ①
ADR-6提醒触发用「事件」而非「轮询」省电，满足 NFR-1

5 · UI / UX 设计

5.1 设计三原则

原则含义反例（必须避免）
不打扰平时几乎隐身，只在关键时刻出现常驻大窗口挡住工作区
一眼可读瞥一眼就知道「现在做什么、还剩多久」需要点击才看到关键信息
零学习成本不看说明就会用复杂图例 / 多级菜单

5.2 信息架构（IA）

浮时
├── 悬浮组件（常驻 · 最重要）
│   ├── 收起态：当前时段 + 倒计时 + 进度 + 下一节
│   └── 展开态：今日时间线 + 下一节
├── 提醒弹窗（事件触发）
│   └── 开始 / 稍后 / 跳过
├── 主窗口（主动打开）
│   ├── 课表（周视图网格）
│   ├── 事项  ├── 统计  └── 设置
└── 托盘菜单（快捷入口）

核心主张：把「悬浮组件」当主角，「主窗口」当配角。用户 95% 的时间只看组件，主窗口只用来改课表。

5.6 核心交互流程（全天主循环）

阶段触发条件系统行为
休眠无临近时段组件显示「当前 / 下一节」，静默
预告距开始 ≤ 5 min轻提醒 Toast 滑入（可关闭）
触发到达开始时间强提醒弹窗 + 声音 / 闪烁
响应用户点击开始→计时 / 稍后→推 10min / 跳过→记录为跳过
无响应30s 未操作弹窗自动收起，记为「未响应」，不重复弹
记录结束时间写 CompletionLog，更新完成率

三个特殊分支

  • 免打扰：处于 Quiet Hours 内 → 降级为静默 Toast，不弹窗、不发声
  • 错过补偿：开机 / 唤醒时扫描 → 对「已过期但未处理」的提醒，以汇总卡片补发一次（不逐条轰炸）
  • 防重：同一 Occurrence 只弹一次；稍后提醒生成新的子 Occurrence

6 · 组件级设计规范（定稿）

组件关键规格
悬浮组件 · 收起态圆角卡片（非胶囊）；四要素：科目 + 倒计时 + 进度条 + 下一节；默认常驻右上角，可拖动；宽 ~220px
悬浮组件 · 展开态悬停 200ms 自动展开（移开 300ms 收起）；今日时间线，当前时段高亮；底部含「下一节 + 打开课表/暂停」
提醒弹窗三按钮（开始 / 稍后 10min / 跳过），不单设「延长」——由「稍后」覆盖；30s 无操作自动收起
轻提醒 Toast右下角滑入，4s 自动消失；不抢焦点
主窗口7 列 × 4 行周网格；阶段切换器置于顶部工具栏；四页签（课表/事项/统计/设置）
托盘左键唤起主窗口；右键菜单：暂停提醒 / 打开课表 / 退出
